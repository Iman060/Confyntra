# Confyntra

Confyntra is a collaboration workspace for startup co-founders. It helps founders think independently while keeping shared startup knowledge, decisions, and progress connected.

The app currently runs in **demo mode**: it uses sample content and browser-local state, and does not require a backend.

## What’s in the app

- **AI workspace** — a private, founder-specific chat experience with scripted demo replies.
- **Shared startup knowledge** — browse attributed findings, evidence labels, and conflicts.
- **Decision proposals** — draft, submit, revise, approve, and request changes to proposals.
- **Committed direction** — view the startup state reflected by committed decisions.
- **Catch-up and startup map** — review team context and explore a structured view of the startup.
- **Onboarding and themes** — create a demo profile and switch between light and dark themes.

## Getting started

### Requirements

- Node.js 20.9 or later
- npm

### Install and run

```bash
npm ci
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). Create a demo account or log in to continue through onboarding to the workspace.

The app defaults to demo mode, so no environment file or API credentials are needed. Demo session/profile information and some workspace changes are stored in the browser; chat history and decision proposals use `localStorage`. This is a prototype, not a secure authentication or shared persistence system.

### Production build

```bash
npm run build
npm start
```

## Configuration and data modes

| Variable | Default | Description |
| --- | --- | --- |
| `NEXT_PUBLIC_BACKEND_MODE` | `demo` | Selects the data adapter. Only `api` opts into the placeholder HTTP adapters. |
| `NEXT_PUBLIC_API_BASE_URL` | — | Public API origin used by the HTTP client. Required if API mode is enabled. |
| `NEXT_PUBLIC_SYNC_POLL_INTERVAL_MS` | `4000` | Revalidation interval for shared live data, in milliseconds. Must be an integer from `3000` to `5000`. |

For local development, leave these unset to use the demo adapters. **Live API mode is not ready for general use:** the backend contract is not present, and feature endpoints and response formats are placeholders. Do not enable `NEXT_PUBLIC_BACKEND_MODE=api` until the backend integration has been implemented and verified.

All `NEXT_PUBLIC_*` values are exposed to the browser. Never put secrets, private API keys, or credentials in them.

In live mode, shared resources revalidate while the page is visible and online; private chat history is not polled. The interval setting does not make the placeholder backend integration ready.

## Project structure

```text
src/
  app/                 App Router pages and global styles
  components/          Shared layout and UI components
  features/            Auth, onboarding, workspace, chat, knowledge, and other features
  lib/                 Configuration, API client, local storage, and shared utilities
  mocks/               Demo seed data
  types/               Shared TypeScript types
```

Main routes:

- `/` — marketing landing page
- `/signup` and `/login` — demo account screens
- `/onboarding` — workspace profile setup
- `/workspace` — the founder workspace

Feature-specific UI, hooks, and data adapters are grouped under `src/features/`. Shared mock data is in `src/mocks/`.

## Notes about the demo

- Demo identity and browser-stored state are for trying the interface only; they are not access control.
- Demo chat replies are scripted, not generated by an AI service.
- Demo data is not synchronized between browsers or devices.
- The API client and per-feature HTTP adapters are scaffolding for a future backend integration, not evidence that a production backend is available.
